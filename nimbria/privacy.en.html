Nimbria Privacy Policy

LightOn Plus Lab (라이트온 플러스 랩) (the "Operator") makes and runs the mobile game Nimbria (the "Service") and handles users' personal information with care. This policy describes only what the Service actually does. Data that is not written here is not collected, and data that is written here is not left out.

This text is short and avoids difficult words. If you have a question, use the in-game contact form (Settings → Info → Contact · Report a bug) or write to support@lightonpluslab.com.

0. What to know first

  • There is no sign-up. When you start, we do not ask for an e-mail address, a phone number or a password. A single random number made by the device the first time you open the app is the whole account. (We receive an e-mail address only if you type one yourself in the contact form because you want a reply — the inquiry is sent even if you do not. See section 1 below.)
  • If you want, you can link the account to a Google account (optional — the game runs just the same if you do not). Once linked, you can come back to that account after deleting the app or changing devices. In that case the only thing the Operator stores is one account number that Google gives, and even that is hashed irreversibly. Your e-mail address and name are not stored (sections 1 and 6 below).
  • Only people aged 14 or over may use the Service (section 9 below).
  • Solo play runs only on the device. Your account, nickname and match records go to the server only when you use online matches. However, error reports sent when the game stops on the device (section 1) are sent during solo play too — they contain nothing at all that can identify the user.
  • None of the above is sent before you give consent on the first screen (before consent the app does not even connect to the server).

However, Cloudflare, which relays the connection, does see the IP address (section 6 below).

More to know when you link to a Google account. The ID token (the signed statement Google sends) carries, besides the account number, your e-mail address and name as well. That ID token travels to the server over an encrypted path, but the server reads only the account number from it and neither reads, nor stores, nor logs the e-mail address and name (there is simply no code that reads them — server/auth.js). The ID token itself is discarded on the spot. What is stored is only one hashed value of the account number and the date of linking.

More to know about reports. The reported person is told neither that a report was made nor who made it — the server sends nothing to the reported person. A report alone does not restrict anyone's use; the Operator looks at the record of that match in person and decides (Terms of Service, Article 9(6)). You can report the same person once per match, up to ten times a day, and reports are accepted only within one day after the match ends.

More to know about inquiries. Only the Operator reads the text you write. The text and the e-mail address are not written to the server log. Please do not write other people's names or contact details. The Operator answers by sending an e-mail to the address you gave (the Operator's mail passes through Google — section 6); the server never sends mail by itself. If you do not give an e-mail address, we cannot answer you. The form goes straight to the game server (encrypted HTTPS); if the server cannot be reached, the text you wrote stays on the screen as it is and you are shown how to send it by e-mail.

Error reports contain nothing at all that can identify the user — the nickname, account number, device number and session key are all left out, and the only device information is "the major version number of the WebView" (the User-Agent string, which carries the device model name, is not sent). Of the address where the error occurred, only the file name is kept. Error reports are sent only after you have consented, and the same error is sent at most once per 1 minute and at most twenty times per launch. The only place that receives these reports is the Operator's own server; no outside tool (crash-reporting SDK) is used.

Sign in with Apple (iOS, optional)

Supported iOS apps let you link an account with Apple as well as Google. Apple’s sign-in screen opens only when you tap the button. Only a keyed hash (HMAC-SHA256) of the Apple user identifier (sub) and the linking date are stored. The original identifier, e-mail address and name are never stored or logged. The app does not request your e-mail or name from Apple; if the identity token includes an e-mail address, the server does not use that field. The token stays in memory only while its signature and nonce are checked, and is not kept on the device, server or in logs. The link follows the account’s retention period and is deleted with the account; it cannot restore a deleted account. Apple learns that the account signed in to Nimbria, under Apple’s privacy policy. The server fetches only Apple’s public keys. Google sign-in on iOS follows the Google data-handling rules above.

Anonymous progress counts (optional)

After first consent, to improve onboarding we count consent completion; entering, performing, skipping or timing out each practice step; the first match start and finish; and returns on days 1 and 7 after installation. This is on by default. Turn it off in Settings → Game → Anonymous progress counts without affecting gameplay. No events are sent while off.

Only six fields are sent: {event, step, appVersion, platform, locale, daysSinceInstall}. The last field is a bucket: 0, 1, 2–6, 7, 8–30 or 31+ days. The install date and flags for events already counted stay only on the device. No account, device or advertising identifier, persistent random ID, nickname, session key, exact installation date or time, cookie or login credential is sent.

The Operator stores only daily aggregate counters for up to 90 days, then deletes them. No per-request row, IP address or User-Agent is stored or logged. Offline or failed events are dropped without retry. Counts are not linked to other information or used to track individuals. They may be sent during solo play too. The network relay sees IP addresses as described in section 6.

2. What we do not collect

Gender, phone number, address, resident registration number, payment information, contacts, photos, files, location information, advertising identifier (AAID), call records, the list of installed apps, microphone, camera.

Your name is neither asked for nor stored. As there is no sign-up step, the account has neither a name nor an e-mail address, and even though Google's ID token carries your e-mail address and name when you link the account to a Google account, the server does not read or store them (section 1). An e-mail address is received only if you write one yourself in the contact form because you want a reply, and it is kept only together with that inquiry (it is not attached to the account). What other users see in the game is the nickname alone.

Your date of birth is not stored either. The first time the app is opened we ask the year and month of your birth to check that you are 14 or over, but that value is used only to work out your age on the spot and is neither stored nor sent (section 9 below).

At present the Service has no advertising, no analytics tools and no payments. If paid products or advertising are introduced, this policy will be changed beforehand, and we will start only after telling you about the newly handled data (for example purchase records). The Android app has only three permissions — internet, network state (to download on Wi-Fi only), and vibration.

There is no free chat and no voice chat. What can be sent in a match is a few fixed signals (pings) and a few fixed short sentences (quick messages). For a quick message, only the number of the chosen sentence is passed to your team, and the server does not keep it. The only thing written in text and shown to other people is the nickname (the text of the contact form goes to the Operator only).

3. Purposes of use

  • Recognising a guest account and keeping it going; making sure nicknames do not collide
  • Linking the account to a Google account so that you come back to the same account after deleting the app or changing devices (Terms of Service, Article 6(6) and Article 11(6))
  • 5v5 matchmaking, running the match, working out results, rank and experience
  • Re-running a match that stopped or went wrong, to find the cause
  • Finding and fixing the place where the game stopped on a device (error report — section 1)
  • Protecting the Service by blocking excessive requests, malformed messages and impersonating nicknames
  • Restricting the use of accounts that break the terms seriously or repeatedly (Terms of Service, Article 9 — its record is in section 4)
  • Receiving reports from other users so that the Operator can check, from the record of that match, whether the terms were broken (a report alone does not restrict — Terms of Service, Article 9(6))
  • Answering inquiries that come through the contact form and by e-mail, and fixing the bugs you told us about

The data is not used for any other purpose. If a purpose is added, this text is changed first and you are told (section 11).

5. We do not give data to third parties

The Operator does not sell or hand over users' personal information to any other person or company.

However, other users in the same match can see public in-match information such as your nickname, chosen hero, position, level, kills / deaths / assists, number of last hits and whether you are alive. This is what a game played together needs in order to run; values that must stay hidden, such as the other team's gold, items and traits, are not sent.

Where an investigative authority or similar body requests it under law through lawful process (a warrant and the like), data may be provided within that scope. If that happens, we will tell you to the extent possible.

7. What is stored on the device (automatic collection tools)

Cookies are not used. Instead the following is kept in the device storage inside the app (WebView). It is on the device and is not sent to the Operator by itself — of the following, only four things go to the server: the device number, the session key, the nickname and the trait loadouts; the rest (progress, settings, consent record, patch state) does not leave the device.

  • Device number, session key, nickname
  • Solo-play progress, match record counts, trait loadouts per hero
  • Settings (controls, display, sound), and whether you have seen the guides
  • Patch state and the downloaded game files
  • The consent record — the version numbers of the terms and the policy you agreed to and the time you agreed, and the single fact that you "confirmed being 14 or over" (the year and month of birth are not kept). You can see it in Settings → Info
  • The time you were blocked after answering that you are under 14 (a single value, so as not to ask again for 24 hours)
  • Two values connected with account linking — one field for whether the server has that feature turned on, and one field for whether you have seen the notice "if you link your account, your records are kept". Both are on the device only and do not go to the server. Google's ID token is not stored on the device either
  • The text you are writing in the contact form is not kept in the device storage — it is only on the screen while the app is open, it is cleared when you send it, and it disappears when you close the app

How to refuse or delete: if you tap Settings → Delete account in the app, the account on the server and the data kept on the device are deleted together. Deleting the app also removes the data kept on the device (the app makes no cloud backup, so it does not move to another device either). If you played in a web browser, you can delete it by clearing the site data in the browser. The detailed steps are in the Account deletion guide.

8. Users' rights and how to exercise them

A user (including a legal representative) may at any time request the following.

  1. Access — tell me what data you hold
  2. Rectification — correct what is wrong (the nickname can be changed directly in the app)
  3. Erasure — delete my account and data
  4. Suspension of processing — stop using it

The fastest way is inside the app: Settings → Delete account. When you tap it, the account row on the server (nickname, rank, match record, progress) is deleted irreversibly, and the account number is erased from the match records.

It can also be done through the in-game contact form (Settings → Info → Contact · Report a bug) or by e-mail: support@lightonpluslab.com. As there is no sign-up information, the only means of recognising you are the nickname and the account number, so please write your nickname in the e-mail and, if an account number is shown in Settings → Info in the app, write it as well. We handle the request within 10 days of receiving it and tell you the result.

Exercising your rights brings no disadvantage. However, if you delete the account, your rank, match record and progress cannot be restored (if you come in again on the same device you become a guest starting for the first time). The same holds even if you linked the account to a Google account — when you delete it, the link disappears too, and the deleted account does not come back even if you sign in with the same Google account (you can start again from scratch with the same Google account).

While your use is restricted, the app does not connect to the server, so you cannot use the "Delete account" button in the app. In that case, send the account number (shown on the app's restriction notice screen) to the e-mail address above and we will delete the account within 10 days. Even after deletion, the reason code and the end time of that restriction remain (section 4).

Automated decisions: matchmaking, rank points, and the deduction of points when a match is not played to the end are worked out automatically by the server according to fixed rules. These concern the running of the game, and no decision is made that affects a user's legal rights or duties. A report takes no action automatically — however many reports pile up, the server only counts them, and a restriction is imposed only after the Operator has looked at the record of the match in person. If a result seems wrong to you, tell us through the contact form or the e-mail address above — a person looks at it.

We do not create and use pseudonymised information separately, nor combine it with other data.

9. Children under 14

This Service may be used only by people aged 14 or over. The first time the app is opened we ask the year and month of your birth to check that you are 14 or over. That value is used only to work out your age on the spot and is neither stored nor sent; only the fact of "confirmed" remains on the device. As we do not ask the day of your birth, the month of birth is counted as fully passed — in the month that contains your 14th birthday you pass only from the following month. This is a count on the strict side, so as not to admit anyone under 14. If you are found to be under 14, you are told on the spot that you cannot use the Service, and you are not asked again for 24 hours (to prevent passing by changing the answer straight away). We do not knowingly collect the personal information of children under 14. If it is confirmed that a user is under 14, that account and its data are deleted. A parent or guardian who finds out that a child has used the Service can tell us at the e-mail address above; we will check and delete it.

10. What we do to keep data safe

  • All communication is encrypted (HTTPS, secure WebSocket). The app blocks unencrypted communication altogether.
  • The device number is not stored as it is — only an account number hashed irreversibly is kept.
  • The Google account number is not stored as it is either — only a value hashed in the same way is kept. So even if the stored file leaked, that value would not tell anyone whose Google account it is.
  • When an account is linked, the server accepts only an ID token that carries the one-time number (nonce) it has just issued to that connection — an ID token obtained elsewhere, or one already used, is rejected.
  • The session key is signed with the server's secret key, and that secret key is kept in a file only its owner can read.
  • Secrets are not written to the logs — keys, tokens and device numbers are masked before they are logged. IP addresses and nicknames are not logged either. The text, e-mail address and account number of the contact form, and the account numbers in reports, are not written to the server log either.
  • The contact form cannot be sent too often from one place (twice per 1 minute, six times per 1 hour). The connecting address used for that count is not stored; only an irreversibly hashed value is kept in memory and cleared every hour.
  • The Service is protected by limiting how much one connection may use (messages per second, bytes, number of commands) and how many connections may be opened from one address.
  • The app puts nothing into cloud backup or device-to-device transfer.
  • The data is on a machine managed by the Operator, and the only person with access is the Operator.
